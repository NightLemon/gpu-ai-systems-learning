# 00 - LLM 行业全景

> 在进入 GPU 架构、CUDA、分布式训练和推理优化之前，先建立一个稳定的一阶认知：模型是怎么训练出来的，工程上真正难的是什么，为什么这些难点会把你带到后续章节。

本章回答三个问题：
1. **模型训练到底在干什么？** → [01-what-is-training.md](01-what-is-training.md)
2. **大模型需要什么样的数据与工程体系？** → [02-data-and-engineering.md](02-data-and-engineering.md)
3. **训练和推理的成本主要由什么决定？** → [03-economics.md](03-economics.md)

## 为什么放在最前面

后面的章节会深入 GPU 架构、CUDA 编程、Transformer 计算、分布式训练、推理优化和基础设施。如果没有一个全局视角，读者很容易把这些内容看成零散技巧，而不是一条完整系统里的局部优化。

这一章的目标不是给出一份市场报告，也不是预测哪家公司最强，而是先把下面几件事说清楚：
- 一个模型从原始数据到上线服务的大致流水线
- 训练和推理分别消耗哪些资源，常见瓶颈在哪里
- 为什么显存、带宽、通信、调度和吞吐会成为后续章节的核心主题

## 阅读预期

这一章会尽量使用稳定的一阶事实。少数数字只表示量级，不代表所有团队、所有模型、所有时间点都适用。

读完后，你应该能回答：
- 预训练、后训练、推理分别在做什么
- 为什么数据处理、集群调度、模型并行和推理引擎都是同一条链上的问题
- 后续每一章是在解决哪个工程约束
